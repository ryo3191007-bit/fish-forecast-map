# 陸っぱり向け沿岸データ取得方針メモ

確認日: 2026-07-28  
対象Issue: #361  
位置づけ: 実釣可能な岸際の地形・水深・ストラクチャー精度を上げるための再開メモ。実装仕様ではなく、次回調査の出発点を固定する。

## 1. 結論

FishForecastMapの沿岸情報は、地点代表座標を中心に広域データを集める方式ではなく、**実釣可能な岸を先に定義し、その岸から概ね150m以内の近岸情報を複数ソースで埋める方式**を優先する。

基本順序は次の通り。

1. 実釣可能な岸を定義する。
2. その岸から0〜150mの近岸水深を取得する。
3. 捨石、消波ブロック、岩礁、船道、ブレイク等のストラクチャーを別レイヤーで整理する。
4. 公開データで埋まらない箇所は本人実測・現地確認で補う。

`unknown` は推測で補完しない。今回の沿岸情報をSCORE v2へ自動接続しない。航海・安全判断に使わない。

## 2. 背景

現在の地点座標は施設・海岸・地区を識別する概略代表点であり、実釣位置、入口、駐車位置、安全な足場、立入可能範囲を保証しない。

そのため、代表点を中心に底質・障害物・水深を検索しても、陸っぱりで「実際に届く範囲」と対応しない可能性が高い。

2026-07-28の海しるAPI PoCでは、唐津東港周辺で底質・海底障害物等のデータ取得自体は成功したが、実釣キャスト圏の情報として扱うには位置・密度が不足した。ESI海岸線も、実釣可能岸の代替としてキャスト距離を算出する用途には不向きと判断した。

この結果を受け、海しるの底質・海底障害物・沈船を主要な近岸データソースとして展開する案は一旦見送る。

## 3. 目指すデータ単位

地点全体を1座標で扱うのではなく、将来的には地点内に「実釣候補岸」を持てる形を検討する。

例:

```text
spot
  └─ shoreFishingSegments
       ├─ 岸壁A
       ├─ 波止B
       └─ 護岸C
```

実釣候補岸には、少なくとも次の状態を持てる設計が望ましい。

- `confirmed`: 実地確認または十分な根拠で確認済み
- `likely`: 複数根拠があるが現地未確認
- `candidate`: 候補
- `prohibited`: 立入・釣り不可を確認
- `unknown`: 判断不能

実装時の正式schemaは別Issueで定義する。

## 4. 水深データの優先順位

### 第1候補: 国土地理院の高精細DEM

通常表示47地点について、国土地理院のDEM1A / DEM5Aのカバレッジを監査する。

特に航空レーザ測深等により海水底面データが存在する地点があるかを確認する。利用可能な地点では、現行GEBCO/ETOPOより近岸形状を細かく捉えられる可能性がある。

次回調査では、次を地点ごとに記録する。

- DEM1A coverage
- DEM5A coverage
- 海水底面を含むか
- 取得単位・形式
- 水平解像度
- 鉛直基準
- 利用条件・加工可否・Web配信可否
- 実釣候補岸から150m以内をカバーするか

### 第2候補: 沿岸海域地形図等の公的沿岸資料

国土地理院の沿岸海域基礎調査・沿岸海域地形図等について、対象地点のcoverageを監査する。

古い調査成果を含むため、港湾改変・浚渫・埋立等がある地点では現況と一致しない可能性を明示する。自然磯・砂浜等で補助資料として使えるかを評価する。

### 第3候補: 港湾・漁港管理者の深浅測量成果

上位sourceで埋まらない重要地点だけを対象に、国土交通省、県、市町村、港湾管理者等が公開する次の資料を個別調査する。

- 深浅測量
- マルチビーム測深
- 浚渫・航路整備資料
- 港湾計画図
- 工事資料・完成資料

全国一括取得を前提にせず、重要地点限定の補完sourceとする。

### fallback: 現行GEBCO / ETOPO

広域表示は現行どおり、GEBCO_2026 15 arc-secondを第一source、ETOPO 2022 60 arc-secondをfallbackとして維持する。

高精細sourceがない地点を推測で補完しない。GEBCO/ETOPOを港内、小さな根、細い瀬等の正確な位置情報として扱わない。

## 5. ストラクチャーは水深と分離する

水深値だけでは、魚が付きやすい構造や根掛かり要因を十分に表現できないため、ストラクチャー情報は別レイヤーとする。

候補項目:

- 防波堤
- 捨石
- 消波ブロック
- 岩礁・磯
- 船道
- ブレイク / かけ上がり
- 水路
- 河口
- 海藻帯
- 人工魚礁等

候補source:

- 公式航空写真・公的地図
- 港湾・漁港管理資料
- 漁場整備資料
- ESI等の岸種別情報（補助根拠のみ）
- 本人実地調査

「存在する可能性」と「実釣位置から届く」を混同しない。

## 6. 本人実測を高信頼レイヤーとして検討する

公開データで近岸150mを十分に埋められない場合、本人実測を有力な補完手段とする。

将来候補:

- キャスト可能な魚探・ソナーによる距離別水深
- 根掛かり位置
- 底質感触
- 岩・捨石・海藻等の現地確認
- キャスト方向ごとのブレイク位置

本人実測は既存のowner-scoped `user_contribution` 方針と同様に、一般調査値とは分離して保持する。未承認投稿で安全・規制・一般調査値を上書きしない。

## 7. 情報に必ず精度・根拠を持たせる

将来的なデータ例:

```json
{
  "distanceFromShoreM": 65,
  "depthM": 7.2,
  "bottom": "unknown",
  "structure": "dropoff",
  "sourceType": "user_sonar",
  "confidence": "high"
}
```

公的資料のみで確定できない場合:

```json
{
  "distanceFromShoreM": 80,
  "depthM": null,
  "bottom": "unknown",
  "structure": "possible_reef",
  "sourceType": "public_map",
  "confidence": "low"
}
```

存在しない値を生成しない。

## 8. 次の一手

次に再開するときは、まず **通常表示47地点の国土地理院DEM1A / DEM5Aカバレッジ監査** を行う。

調査ゲート:

1. 実釣候補岸から150m以内をカバーできるか。
2. 現行GEBCOより実用上明確に細かいか。
3. 海底面として解釈できるデータか。
4. 出典・取得日・鉛直基準・解像度を記録できるか。
5. 加工・アプリ表示・Web配信条件を満たせるか。

47地点全部で採用できる必要はない。coverageがある地点だけ高精細化し、ない地点は現行広域sourceを維持する。

## 9. 非目標

この方針メモだけでは次を行わない。

- SCORE v2変更
- 既存spotId変更
- 既存代表座標の変更
- Supabase migration
- 有料API・有料地図・有料データ購入
- 航海用・安全判断用データの提供
- 不明値の推測補完
- 海しる底質・海底障害物・沈船の47地点一括展開
